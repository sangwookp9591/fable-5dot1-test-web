당신은 인터랙티브 웹·디자인 시니어 리뷰어다. 아래 프로젝트를 냉정하게, 칭찬 없이, 구체적으로 리뷰하라. 한국어로 답한다.

## 대상
- 저장소: 현재 디렉터리 (Next.js 16 + Bun, React Three Fiber, GSAP ScrollTrigger). 박상욱 개발자의 인터랙티브 포트폴리오. 마스코트 "아잉"(고양이) 이 3D 스튜디오 방 안에서 스크롤에 따라 안내한다.
- 기준 문서: `fable-5.1-interactive-web-spec.md` (구조·품질 기준), `ai-ng-tone-rules.md` (문구 말투 규칙), `docs/fable-experiment/*.md` (구현자가 쓴 자기 검수).
- 첨부 스크린샷: docs/fable-experiment/screens/ 의 데스크톱 1440 · 모바일 390 섹션별 화면. (첨부 이미지도 참고)
- 코드: `experience/` 아래 전부, `app/`, `public/aing`(영상 목록만), `scripts/aing`.

## 리뷰 항목 (각 항목마다: 문제 → 근거(파일·줄 또는 스크린샷) → 고치는 방법. 심각도 High/Med/Low)
1. 첫 인상 3초: Hero 가 "이 사람이 누구고 뭘 만들었는지" 를 전달하나. 카피가 tone rules 를 지키나 (추상어·AI 티 나는 표현·기술 이름 먼저 나오는 문장).
2. 시각 디자인: 타이포 위계, 색, 패널(반투명 카드)이 3D 위에서 읽히나, 3D 방의 완성도(가구 배치·조명·비율), 아잉과 3D 의 어울림. 어디가 "AI 가 만든 데모" 처럼 보이는가.
3. 인터랙션의 이유: 각 섹션 인터랙션(경력 보드, 숫자 카운트업, 언어 슬라이더, 고치는 과정 4단계, 스튜디오 투어, 검수 라이브 지표)이 내용을 더 잘 전달하는가, 아니면 장식인가. 빼야 할 것.
4. 스크롤 경험: sticky 구간 길이(vh) 가 적절한가, 지루한 구간, 너무 빠른 구간. 역방향 스크롤·빠른 스크롤에서 깨질 수 있는 코드 경로.
5. 아잉 오버레이 엔진 (`experience/mascot/`): 상태 전환 로직의 버그 가능성, race condition, 메모리/decode 비용, Safari 경로.
6. Three.js (`experience/scene/`): 렌더 비용, demand 모드의 빈틈, 카메라 키프레임 품질, 모바일 처리, 실패 처리.
7. 접근성·반응형: 키보드, 스크린리더, reduced-motion, 375~430 모바일, 1024 태블릿. 터치 타깃.
8. 코드 품질: 구조, 중복, 타입, 네이밍, 죽은 코드, 컴포넌트 크기, 테스트 부재.
9. 포트폴리오로서의 설득력: 채용 담당자가 60초 안에 얻는 정보. 빠진 것(연락·이력서·프로젝트 링크 접근성).

## 출력 형식
- 맨 위에 총평 5줄 (점수 10점 만점, 항목별 점수 표).
- 그 다음 High 부터 정렬된 이슈 목록 (최대 25개). 각 이슈는 3~5줄.
- 마지막에 "지금 당장 고쳐야 할 5개" 를 순서대로.
- 코드를 수정하지 말고 리뷰만 한다.
