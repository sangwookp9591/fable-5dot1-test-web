# 02 · Concept — 아잉 스튜디오

## 한 문장

> 아잉이 일하는 작은 작업실을 스크롤로 둘러보며, 박상욱이 실제로 만든 것들을 방 안의 물건에서 꺼내 본다.

## 왜 "방" 인가

spec 의 Design Direction: 사람이 실제로 일할 것 같은 공간, 따뜻한 소재, 실제 가구, 약간의 장난기.
포트폴리오의 내용도 "화면 → 서버 → 배포 → 운영" 처럼 한 사람의 작업 범위가 넓어지는 이야기라서,
책상·벽·책장·서버 랙 같은 물건 하나하나에 내용을 붙이면 설명 카드를 쌓지 않아도 된다.

## 물건 ↔ 내용

| 방 안의 물건 | 연결된 내용 | 어떻게 반응하나 |
|---|---|---|
| 책상 위 모니터 | ZIVO 이용자용 웹 · 14개 언어 | 섹션마다 화면 내용이 바뀐다 (canvas texture). 스튜디오 섹션에서는 실제 이용자용 웹 캡처(`zivo-app.jpg`)를 폰 프레임으로 |
| 벽 보드 (책상 위) | 경력 4줄 | 스크롤할수록 한 줄씩 채워진다 |
| 벽 TV | 백오피스 157개 화면 | 실제 백오피스 대시보드 캡처(`public/screens/zivo-admin.jpg`)가 투어 2번째 정거장에서 밝아지고, 타일이 차례로 켜진다 |
| 미니 서버 랙 | 배치·워커·API 분리 | 한 덩어리가 세 덩어리로 벌어지고 LED 가 켜진다 |
| 노트북 | 여기가게 숏폼 앱 | 투어 4번째 정거장, 카메라가 가까이 간다 |
| 책장 피규어 | 직접 써본 AI 도구들 | AI 섹션 카메라가 책장을 본다 |
| 벽 포스터 | 아잉 | 결과 화면에서 방 전체와 함께 보인다 |
| 아잉 자리 (책상 뒤) | 고치는 과정 | 아잉 WebM 이 3D 좌표에 앵커되어 책상 뒤에 앉아 타이핑한다 |

## 흐름 (experience state)

```
INTRO   아잉이 걸어 들어와 묻는다. "박상욱, 진짜 그렇게 다 해?" → [바로 보기] 누르면 모니터가 켜진다
CAREER  벽 보드. 4개 회사가 한 줄씩. 아잉이 가리킨다
ZIVO    숫자 4개 카운트업 → 14개 언어 슬라이더 (쿠키 → URL). 아잉이 놀란다
LOOP    핵심. 문제 → 원인 → 해결 → 다시 실행. 터미널과 모니터가 같은 내용을 보여준다. 아잉은 think → review → type → celebrate
STUDIO  카메라 투어: 책상 → 벽 TV → 서버 랙 → 노트북. 물건마다 카드 하나
AI      책장의 피규어. "새 AI 가 나오면 후기보다 먼저 켜봅니다"
REVIEW  이 사이트 자체의 검수 결과 + 방문자 브라우저에서 실제로 잰 LCP/CLS/INP/FPS
RESULT  방 전체. "그래서 박상욱, 쓸 만했을까요?" 아잉: "오… 꽤 하는데?" → 인사 후 퇴장
```

## 말투

`ai-ng-tone-rules.md` 그대로. 예: "Agentic Intelligence" 대신 "코드 짜고 끝? 이번엔 안 됩니다".
아잉의 `냥` 은 결론 순간 두 번만: 인트로 두 번째 대사, 마지막 인사.

## 뺀 것

- 3D 안에 글자를 많이 넣는 것 (읽기 어렵다) → 글은 DOM 패널, 3D 는 물건과 빛만
- 마우스 parallax 로 방 전체가 흔들리는 것 → 램프 빛과 카메라 시선만 아주 살짝
- WebGPU → 오브젝트 수가 적어 이점이 없다. WebGL 로 충분 (spec §10 판단)
- 사운드 → 자동 재생 금지이고, 이 콘텐츠에서 공간감보다 방해가 클 것 같아 v1 에서는 넣지 않음
